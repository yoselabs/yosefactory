# Transcript Log Subscriber — Design

**Status:** Draft · 2026-04-18
**Author:** Claude (with Denis)
**Scope:** Add a human-readable stage transcript to MLflow artifacts, capturing assistant narrative, tool calls, TodoWrite state, and subagent activity with parallel-safe labels.

---

## Motivation

Today MLflow captures stage metrics and span traces, but there is no narrative record of what the agent actually *said* and *did* during a stage. Denis needs this for local evaluation runs — to A/B test prompts, spot where an agent got stuck, and see subagent internals when things go sideways.

Existing log sources don't fit:

- `rich.Live` console panel — lives on screen only, ANSI-colored, not persisted.
- `GhActionsLogSubscriber` — plain text but only emits `::group::` markers + tool names, no assistant text.
- `.a2sdlc/logs/*.log` (Python logger JSON) — only wired to the GH dispatch path, and even there it captures pipeline breadcrumbs, not per-tool narrative.

We need a new artifact: a chronological, UTF-8-only, human-readable transcript uploaded to MLflow per stage.

## Non-goals

- **Not** a structured log for programmatic parsing. That's what `<stage>-output.json` is for.
- **Not** a replacement for MLflow traces. Traces give span tree + attributes; transcripts give human reading.
- **Not** a faithful SDK JSONL capture. We synthesize a readable stream from the progress bus; if the SDK's raw JSONL is ever needed, it lives at `~/.claude/projects/<munged>/<uuid>.jsonl`.
- **Nested subagent-of-subagent** (A spawns A.1): out of scope. Flatten any deeper nesting onto the nearest labeled parent.

## Design

### Event taxonomy additions

Three new events on `a2sdlc.evaluation.progress`:

```python
@dataclass
class AssistantText:
    text: str
    timestamp: float                 # seconds since stage start
    agent_label: str | None = None   # None = top-level agent; "A"/"B"/… = subagent

@dataclass
class SubagentStart:
    label: str                       # "A", "B", …
    agent_id: str                    # tool_use_id truncated to 8 chars
    prompt: str                      # subagent's task prompt
    timestamp: float

@dataclass
class SubagentEnd:
    label: str
    result: str                      # tool_result content, may be truncated upstream
    timestamp: float
```

`ToolEntry` gets one new optional field: `agent_label: str | None = None`. Existing call sites pass `None`, preserving behavior.

### Runner changes (`pipeline/runner.py`)

Maintain per-stage state:

```python
_label_by_tool_id: dict[str, str] = {}  # tool_use_id -> "A"/"B"/…
_next_label_idx: int = 0                # increments across the whole stage, never reused
```

For each streamed SDK message:

1. Read `parent_tool_use_id` off the message (or None for top-level).
2. Resolve `agent_label = self._label_by_tool_id.get(parent_tool_use_id)` — `None` means top-level.
3. For each block in the message:
   - **Text block** (assistant): emit `AssistantText(text, elapsed, agent_label)`.
   - **Tool-use block** with `name == "Task"`: assign next label (A, B, C, …), store `_label_by_tool_id[tool_use_id] = label`, emit `SubagentStart(label, agent_id=tool_use_id[:8], prompt=extracted_prompt, elapsed)`. Also emit the existing `ToolEntry(name="Task", target="spawning Agent <label>", agent_label=agent_label)` for the parent's tool log.
   - **Tool-use block** (other): emit `ToolEntry(name, target, agent_label)` as today, now tagged.
   - **Tool-result block** for a known subagent tool_use_id: emit `SubagentEnd(label, result, elapsed)`.

Labels are generated by `chr(ord("A") + idx)` for idx 0–25; beyond 26 use `"AA"`, `"AB"`, … (unlikely in practice but trivial).

### Subscriber (`adapters/transcript_log_subscriber.py`)

```python
class TranscriptLogSubscriber:
    def __init__(self) -> None:
        self._lines: list[str] = []
        self._seen_subagents: set[str] = set()

    async def handle(self, event: ProgressEvent) -> None: ...
```

- Append-to-memory until `StageEnd`; then write to temp file and call `mlflow.log_artifact(path, artifact_path=None)` so it lands at the root of the active MLflow run.
- Artifact filename: `<stage>-transcript.log` (e.g. `spec-transcript.log`).
- No ANSI ever. Plain UTF-8. Pure ASCII prefixes + a few emoji for sections (📋 tasks, ✨ milestones, ← done).

#### Line format

| Event | Rendered |
|---|---|
| `StageStart` | `[00:00] stage spec start — session smoke6, model claude-sonnet-4-6, branch a2sdlc/smoke6` |
| `AssistantText` (top-level) | `[00:05] [assistant] Let me start by reading the ticket...` |
| `AssistantText` (subagent) | `[00:14] [Agent A] [assistant] I found 3 matches...` |
| `ToolEntry` (top-level) | `[00:07] [tool] Read ticket.md` |
| `ToolEntry` (subagent) | `[00:14] [Agent A] [tool] Glob "**/*.py"` |
| `ToolEntry name="Task"` | `[00:12] [tool] Task (spawning Agent A)` |
| `SubagentStart` | `[00:12] [Agent A] id=abc12345 — "Find all files matching pattern X"` |
| `SubagentEnd` | `[00:18] [Agent A] ← done: Found 3 matches in foo.py, bar.py, baz.py` |
| `ToolEntry name="TodoWrite"` | multi-line, see below |
| `Milestone` | `[00:31] ✨ milestone: brainstorming invoked` |
| `StageEnd` | `[03:46] stage spec OK — tokens 1.2k/3.1k, cost $0.42, 47 turns` |

TodoWrite rendering pulls the full list from the input (not just the target string) and renders status icons:

```
[01:05] 📋 tasks:
           ✅ Write spec doc
           🔄 Write plan doc
           ⬜ Run make check
```

Icons: `✅ completed`, `🔄 in_progress`, `⬜ pending`.

#### Truncation

Assistant text over 500 chars truncates to `text[:500] + f"… (+{len(text)-500} chars)"`. SubagentEnd results truncate at 200 chars with the same suffix. Raw length is preserved in MLflow span attributes (separate story), so nothing is lost permanently.

#### Failure isolation

The progress bus already catches per-subscriber exceptions and removes the failed subscriber for the rest of the stage. No new error handling needed.

### Wiring (`cli_local.py`)

Register alongside `MlflowTraceSubscriber` when `sink is not None`:

```python
if sink is not None:
    from a2sdlc.adapters.mlflow_trace_subscriber import MlflowTraceSubscriber
    from a2sdlc.adapters.transcript_log_subscriber import TranscriptLogSubscriber

    progress_state.subscribe(MlflowTraceSubscriber())
    progress_state.subscribe(TranscriptLogSubscriber())
```

`pyproject.toml` `ignore_imports` gains one entry:
```
"a2sdlc.adapters.transcript_log_subscriber -> a2sdlc.evaluation.progress",
```

### Testing

**Unit — subscriber (`tests/adapters/test_transcript_log_subscriber.py`):**
- Assistant text rendering (top-level + subagent)
- ToolEntry rendering (with and without agent label)
- TodoWrite expansion to icon list
- SubagentStart/End formatting
- Truncation at 500 / 200 chars with `… (+N chars)` suffix
- Multiple parallel subagents interleaved — labels stay stable
- On `StageEnd`, mock `mlflow.log_artifact`; assert called with correct path and filename

**Unit — runner label assignment (`tests/pipeline/test_runner_subagent_labels.py`):**
- One sequential subagent: emits `SubagentStart("A", …)` then `SubagentEnd("A", …)`
- Two parallel subagents: `A` and `B` both get `SubagentStart` before either `SubagentEnd`
- Two sequential subagents: second gets `B`, not reused `A`
- Nested messages tagged with correct `agent_label` based on `parent_tool_use_id`

**Integration (`tests/pipeline/test_dispatch_progress.py`):**
- Register `TranscriptLogSubscriber`, run dispatch with a fake runner emitting a scripted event stream, assert the final artifact contents contain expected lines in expected order.

### Effort / risk

~30 runner lines (label map, event emission), ~150 subscriber lines, ~100 test lines. One SDK quirk risk: we need to confirm `parent_tool_use_id` is reliably set on nested assistant messages in claude_agent_sdk v0.1.56 before relying on it; if not, we fall back to shallow rendering (Agent A entry shows the prompt + result, no nested internals) and revisit when the SDK exposes it.

## Open questions

1. Should the transcript also include **metrics snapshots** (cumulative tokens/cost) periodically, or only at stage end? Current design says end-only — assistant narrative + tools + subagents is the story; metrics are noise for human reading. Reconsider if users ask.
2. Should `TranscriptLogSubscriber` also write the transcript to `.a2sdlc/logs/<stage>-transcript.log` on disk, independent of MLflow? Useful if MLflow is disabled (`--no-track`). Easy add; not strictly required for the current story.
